# 网络发现的取舍：一次性探测、只信主机与端口

> **状态：已实施（2026-11-07）。** 范围：`crates/dae-core/src/fs/discovery.rs`、
> `crates/dae-qt/src/network_discovery.rs`、`qml/Sidebar.qml`、
> `qml/ConnectDialog.qml`、`qml/ShellWindow.qml`。
> 相关：`docs/files-parity.md` §5.8、§12.1 的 R-2、§12.7。

## 0. 结论

侧栏的「网络」段回答一个问题：**这台机器所在的局域网里，现在有什么文件服务在
广播？** 答案是 1.5 秒的一次性探测结果，用完即弃，不常驻守护进程，不保存，
不借用广告方的任何说法（TXT 记录）来自动填表。点击一行只是把协议、主机、端口
填进连接对话框；账号、密码、访问哪条路径，仍然由用户确认。

## 1. 一次性探测，而不是常驻守护

`discover(timeout)` 每次创建一个 `ServiceDaemon`，对
`_smb._tcp` / `_sftp-ssh._tcp` / `_webdav._tcp` 各 `browse` 一次，在时限内收
`ServiceResolved`，到点 `shutdown`。

选的是一次性，理由是成本与收益不对称：

- 常驻守护要持续收发组播，笔记本上直接反映为唤醒与耗电，而侧栏这份列表只有在
  用户找服务器时才有意义；
- 结果不持久化，因为「上次看到过」和「现在还在」是两件事，后者是用户真正要的；
- 刷新入口就在段标题右侧，愿意付第二次 1.5 秒的用户点一下即可。

`NetworkDiscovery.scanned` 只保证同一进程不重复探测（第二个窗口、撕出的标签页），
不阻止手动刷新。

## 2. 只信主机与端口

`ServiceInfo` 的 TXT 记录是**广告方写的**。它可以包含用户名、共享路径、甚至口令。
把它读进对话框意味着：局域网里任何一个能发组播的进程，都能让 dae 预填一份看起来
可信的凭据。因此：

- 只读取实例名、主机名、端口、地址；
- 实例名只用于显示（截到第一个 `._` 之前）；
- 主机名去掉尾点；没有主机名时回退到第一个地址，保证对话框有东西可填；
- 协议由查询的服务类型决定，不读广告内容。

这不是安全边界（连接仍要用户点「连接」），而是不让界面替用户做信任决定。

## 3. 去重与排序

同一服务经常同时以多个实例名、多个地址、多个接口回答。归并键是
**协议 + 折叠主机名 + 端口**：

- 实例名不参与键：同一个 NAS 换个广播名不该出现两行；
- 地址合并去重后排序，界面只显示实例名与协议，地址留给后续连接诊断；
- 排序固定为 SMB → SFTP → WebDAV →（其他），与连接对话框的协议行一致；
- 端口为 0 或没有主机也没有地址的条目直接丢弃——它们不可连接。

## 4. 失败就是空表

没有组播的网络、被防火墙拦下的组播、沙箱里没有套接字权限：`ServiceDaemon::new`
或 `browse` 失败时记一条 debug 日志并返回空表。发现不是导航的前置条件，把启动
流程或侧栏卡在「等待网络」上比没有这个功能更糟。

## 5. 运行时证据

Windows，隔离 `APPDATA`，本机临时广告器注册 `Dae Smoke NAS._smb._tcp`：

- 侧栏出现「网络」段与「Dae Smoke NAS  SMB」一行；
- 点击后连接对话框以 SMB、`dae-smoke.local`、`445` 打开，账号与密码为空
  （UIA 读到的两个 Edit 值为证）；
- `cargo test -p dae-core --lib` 覆盖去重、协议区分、主机回退、丢弃无效条目与
  实例名截断；`cargo test -p dae-qt --lib` 覆盖单例默认态。

Linux 运行时仍待真机按 `docs/qt-platform-parity.md` §4 的「网络发现」行补测。

## 6. 仍然存在的边界

- **跨网段不可见**：mDNS 只到本地链路，VLAN/子网外的服务器要靠手动填表；这也是
  系统文件管理器的行为。
- **WS-Discovery 未做**：Windows 的网络位置还有一套 SOAP 发现，v1 不实现。
- **没有「已发现但连不上」的提示**：发现只说明有人广播，不证明 445/22/80 可达；
  失败在连接测试里才出现。
- **结果不缓存**：每次启动探一次；网络变化后要点刷新。
