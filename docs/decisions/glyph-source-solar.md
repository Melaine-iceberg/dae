# 界面图标换成 Solar Icons

> 日期：2026-11-13 · 状态：已实施（Windows 本机验证，macOS/Linux 未跑）
> 相关：`qml/Glyph.qml`、`qml/SolarMarks.js`、`docs/ui-instrument-migration.md` §6.4

## 问题

`qml/Glyph.qml` 里 64 个标记（407 行路径数据）是照着原型 sprite 手抄的，
`docs/ui-instrument-migration.md` §6.4 规定「图形数据只有一个来源」。实际结果是：

- 新增一个标记要手绘坐标，10/12/14/16/28/38 dp 六种尺寸都要肉眼校一次；
- 手绘的近似形状已经在漂移（§6.4 自己记过「设置画成太阳、链接画成纸张」）；
- 文件行早就换成 `DriftSheet.qml`，`Glyph` 现在只服务**非文件**的构件：侧栏目的地、
  标签页、菜单、工具栏、空状态、传输队列，以及按 category 的少数文件标记。

手绘的成本不在渲染，而在**每次增删图标的描图**。

## 决定

**几何来自 Solar Icons 的 `linear` 风格，`Glyph.qml` 只留渲染器。**

- 数据放 `qml/SolarMarks.js`（`pragma library`），一个 `kind` → `[{ d, f, s, w }]` 的表，
  与旧的 `marks` 同构，所以调用方一行没改。
- 版本钉在 `@solar-icons/static@2.5.0`，路径数据**按原样拷贝**（小数保留两位），
  文件头记来源、映射表与 MIT 许可全文。上游改了形状就重新拷贝，不在这里改。
- 风格只取 `linear`：24 单位网格、1.5 单位描边，正好是 `Glyph` 已有的描边式标记。
  `bold-duotone` 是 Solar 的「实心 + 次级层」，和本项目的 `wash` 概念同源，但一屏
  全是实心块会压过文字，故只保留 `folder` / `tag` 两个 `s` 标记。
- 六个标记留在本项目：macOS 三色灯的字形（`windowMin/Max/Close/FullScreen/ExitFullScreen`，
  画在 12 dp 圆点里，没有对应图标）与空间标记 `diamond`。几何按 1.5× 从 16 网格放大，
  是数据文件里唯一不是 Solar 的部分。

## 渲染规则没有变

| 规则 | 实现 |
|---|---|
| 描边不随尺寸缩放 | `lineWidth = 1.2 × max(1, 宽度/16) × 24 / 宽度`（单位是网格单位，折算回设备像素后 ≤16 dp 恒为 1.2 px） |
| 剪影 = 淡填充 + 描边 | `s` 标记先以 `wash`（0.3）填充再描边 |
| 单色 | 填充色与描边色都取 `tint`，数据文件里没有颜色 |
| 24 dp 网格 | Solar 自带 2 单位留白，16 dp 下画幅约 13.3 px（旧 sprite 约 12 px），视觉上略大 |

有一处必须改：旧 `trace()` 只认 `M/L/Q/C/Z`，而库的路径数据全是 `A` 圆弧、相对命令
与隐式重复。`Glyph.qml` 现在解析完整 SVG 语法，圆弧按规范的端点→圆心转换后切成
≤90° 的三次贝塞尔（每个圆角都走这条路径）。没有引入 SVG 模块，也没有栅格化：
Canvas 仍是每个标记一个，尺寸/色调变化重绘一次。

## 为什么不选别的

按 16 dp 实测线宽与形体判断（出厂线宽 × 16/24）：

- **Iconoir**（1.5/24 → 1.0 px，MIT）：几何最接近「仪器」，但 UI 覆盖少，且没有
  双色层；作为备选记录在此。
- **Tabler**（2/24 → 1.33 px，MIT）：覆盖最全（6287，含 23 个 `file-type-*`），
  但线宽比本项目重，且 2 px 的圆角在 10 dp 菜单里会糊。
- **Lucide**（2/24，ISC）：只有描边，没有实心变体，和「文件夹是实心剪影」冲突。
- **Phosphor**（256 网格，MIT）：`file-*` 覆盖最好（40 个，含 `file-rs`），但形体
  圆润、内部笔画在 16 px 下约 1 px，离这套界面最远。
- **继续手绘**：只省一次选型，成本落在之后每一个图标上。

## 验证

- `cargo build -p dae-app` 通过；`qmllint qml/Glyph.qml` 无告警。
- `kind` 覆盖核对：QML 与两个 `glyphKind()` 映射里出现的所有取值都在 `SolarMarks.js` 中
  （顺带补上了 `chevronRight`——标签页「关闭右侧标签页」原本引用的名字在表里不存在，
  那一行一直没有图标）。
- 应用内目视：侧栏（驱动盘/星标/展开箭头）、概览便签（主目录/桌面/文档/下载/图片/
  音乐/视频）、命令面板（文件、搜索、文件夹剪影）、标签页关闭，均按 1.2 px 描边渲染，
  圆弧无断裂；文件夹是 30 % 填充 + 描边。
- 未覆盖：备选库只按 SVG 数据与矢量图比对，没有逐个在应用里替换做过 A/B；
  长路径数据的首次绘制成本没有单独计时（`docs/decisions/listing-shell-costs.md` §7
  的 `Glyph` 重绘项本来就未测，这次没有把它变得更差，但也没有补测）。
