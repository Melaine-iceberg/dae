# 设计原则

状态：**已采纳**（2026-10-08，取代此前的「液态玻璃」方向）

视觉与交互改动以本文为准。**token 的唯一来源是 `src/App.css`**；这份文档只解释
「为什么 token 是这个形状」，以及「改之前该问什么」。数值以 `App.css` 为准，两者不一致时
改文档。

## 一句话

> **让实色设计本身成立，系统材质只作为锦上添花。**

三个平台上看起来协调，靠的不是模仿其中任何一个，而是：外壳安静、中性，颜色只留给内容；
只在少数几处向平台借东西（见 [§3](#3-向平台借什么)）。

---

## 1. 为什么不是液态玻璃

液态玻璃是 Apple 的品牌语言。放在 Windows 和 Linux 上，它看起来像套了别人系统的皮；
更实际的问题是**它依赖背后有东西可透**，而这三个平台恰好不一致：

| 平台 | 能给窗口什么背景 |
|---|---|
| macOS | vibrancy（侧边栏材质） |
| Windows 11 | Mica / Acrylic |
| Linux | 只有 niri（Wayland）能拿到合成器模糊，其余桌面都是 `none` |

旧方案里的磨砂、高光边、泛光、粉紫渐变都是纯 CSS，三个平台都画；但它们要靠「背后有壁纸」
才像玻璃。没有壁纸可透的桌面上，它只剩一层假玻璃。再加上文件列表是以文字为主的界面，
半透明表面压低了可读性的余量（旧注释里为此专门量过菜单必须有 90% 的实色密度）。

**所以这条路的问题不是做得不够好，而是前提在三个平台上不成立。**

### 凭什么重新考虑

下面任何一条成立，这个决定值得重开：

- 产品定位改成 macOS 优先，另两个平台降级支持。
- Windows 和主流 Linux 桌面都有了与 macOS 等价、且 WebView 里能稳定使用的原生材质。
- 有实测数据表明实色外壳在用户群里的可读性或辨识度明显更差。

## 2. 五条原则

1. **实色是设计，材质是点缀。** 任何表面在 `--pane-alpha: 100%` 时必须是完整的成品。
   拿掉系统材质，画面不能缺东西。
2. **面板靠色差和发丝线分开，不靠阴影。** 阴影只留给浮起的层（菜单、对话框、命令面板、拖动影子）。
3. **颜色属于内容。** 外壳是中性冷灰；文件夹的黄、文件类型的六种色相、缩略图才是画面里的颜色。
   外壳上唯一饱和的是强调色，而它来自用户的系统设置。
4. **刻度是封闭的。** 字号、圆角、动效时长和曲线、阴影档位都是有限集合。
   需要一个集合外的值，说明要改的是刻度，不是这一处。
5. **状态用填充和墨色表达，不用形状和装饰。** 选中是一层强调色底，悬停是一层墨色底；
   不加发光、不加渐变，导航行、菜单行和命令面板行也不加描边环。
   唯一的例外是文件行与网格单元选中时的 1px `--selection-edge` 发丝线（见 [§7](#7-颜色)）。

## 3. 向平台借什么

借的是**平台拥有的值和行为**，不借平台的视觉风格。

| 借什么 | 怎么借 | 在哪 |
|---|---|---|
| **强调色** | 读取系统强调色，整个窗口随之重新着色。Windows 读注册表，macOS 读 `NSColor.controlAccentColor`，Linux 读 freedesktop portal。没有时回退到默认深青。 | `src/lib/system-accent.ts`、`src-tauri/src/system_accent/` |
| **明暗** | 跟随系统，也允许在应用内固定。 | `index.html` 的启动脚本 |
| **窗口控件的位置与行为** | macOS：红黄绿在左，字形悬停才出现，窗口失焦变灰。Windows / Linux：右侧的标题栏按钮组；Windows 保留 Snap Layout 悬浮层。三者都是自绘（`decorations: false`）。 | `window-controls.tsx`、`.traffic-lights`、`.window-control` |
| **字体** | 一律用平台自己的 UI 字体（SF、Segoe UI Variable、Cantarell/Noto），中文族跟在后面。**不打包字体**。 | `--font-sans`、`--font-mono` |
| **快捷键标记** | ⌘ 与 Ctrl 按平台显示。 | `formatBinding` |
| **窗口材质（点缀）** | Mica / Acrylic / vibrancy 只从画布透出一点（见 [§6](#6-系统材质接缝)）。 | `data-window-material` |

**不借的：** 各平台各自的控件外观、标题栏样式、圆角语言、阴影语言。这些在三个平台上本来就不一样，
借了就等于把不协调放进来。

### 为什么不打包字体

曾经打包过 Inter Variable + Sarasa UI SC，换来三个平台渲染一致，代价约 3.1MB；
再加上等宽字体 4.8MB，任何 `font-mono` 的界面都会把一个数 MB 的 CJK 字体拖进启动路径。
dae 本质上是系统文件管理器和终端之上的一层壳，平台自己的字体是意图而非妥协。
代价是字重保真度（`500` 在只有 Regular / SemiBold / Bold 的平台上会被吸附到最近的档位），
这是有意接受的。

## 4. 封闭的刻度

### 字号（六档，不允许集合外的字号）

| 名称 | 大小 | 用途 |
|---|---|---|
| `title` | 18px | 页面、对话框、分区标题 |
| `lead` | 15px | 唯一的大输入框：命令面板的搜索框 |
| `body` | 14px | 主力：行、控件、表单文字 |
| `caption` | 13px | 次要信息、描述、分组标题 |
| `micro` / `label` | 12px | 紧凑的外壳（状态栏、容量、徽标）/ 表格与菜单的分组标题 |
| `nano` | 11px | 键帽、徽标字母 |

没有展示级字号：`title` 就是窗口里最大的东西，文件管理器的首页是一份地点列表，不是落地页。
`label` 不做字距拉开、不转大写——这种处理对汉字无效，对拉丁字母也只是装饰。
数字列（大小、日期、计数）一律 `tabular-nums`，这样列对得齐。

### 圆角（基准 8px）

| 步 | 大小 | 用在（以代码里的实际用法为准） |
|---|---|---|
| `xs` | 4px | 键帽、行内代码、「已选 N 项」的小底 |
| `sm` | 5px | 按钮、输入框、表头单元格、小图 |
| `md` | 6px | 文件行与网格单元、侧栏行、菜单、标签与标签板 |
| `lg` | 8px | 标签凹槽、Toast、操作条、外部拖入的覆盖层 |
| panel | 10px | 内容面板（侧栏、文件区、终端） |
| `xl` | 12px | 命令面板与对话框 |

规则：**每一档都是 `--radius` 加减一个常数**，所以整体圆润度只改一个值。
面板（10）比对话框（12）小一档：窗口自己有一个角，对话框没有可比较的对象。
只有状态点和容量条用全圆；其余地方没有胶囊。

### 动效

| | 值 |
|---|---|
| 时长 | `instant` 100ms · `fast` 150ms · `normal` 200ms · `slow` 300ms |
| 曲线 | `standard`（状态变化）· `standard-accelerate`（离场）· `spring-fast`（变换与进场）· `spring` / `spring-slow`（大面积进场） |

- **没有过冲。** 越过目标再弹回去的曲线属于机械感，这套语言不用。曲线名里的 `spring` 只是角色名（「正在抵达的东西」）。
- **颜色类过渡只用 `standard`。** 用缓出曲线做悬停底色，看起来像悬停在追指针。
- 浮层进场只有淡入加 3px 位移和 0.985 的缩放；对话框不从中心放大。
- `prefers-reduced-motion` 下所有动画与过渡塌缩成近乎瞬时。

### 阴影（四档，只给浮起的层）

`xs` / `sm` / `ambient` / `lg`。亮色里透明度在 2.5% – 8% 之间，几何形状（多层、大模糊）而不是透明度承担层次；
暗色里黑色阴影在近黑底上几乎看不见，所以档位更高（22% – 46%）。
**面板本身**亮色有一层 `--panel-shadow`（1px 偏移、2px 模糊、6%），暗色是 `none`。

## 5. 表面与层级

两级加一条线：**画布 → 面板（纸）→ 浮层**，边界是 `--border` 发丝线。

| | 亮色 | 暗色 |
|---|---|---|
| 画布 `--background` | `#f2f4f6` | `#191918` |
| 面板 `--card` | `#ffffff` | `#252525` |
| 浮层 `--popover` | `#ffffff` | `#2e2e2e` |
| 悬停 / 凹槽 `--accent` `--muted` | `#eef0f3` | `#323232` / `#2c2c2c` |
| 发丝线 `--border` | `#e1e4e9` | `#3a3a3a` |
| 墨 `--foreground` | `#31353b` | `#e9e9e9` |
| 次要墨 `--muted-foreground` | `#5c626b` | `#adadad` |

- 中性色**不带色相**。窗口里已经有六种内容色相、一个文件夹金和一个强调色，
  再给中性色加色相就多了第四个声音，在每一次悬停和每一条发丝线上重复。
- **标签栏**：凹槽 = 墨色的 6% 铺在画布上；当前标签是一块「纸」，带发丝线和一点接触阴影。
  暗色下这块板用 `--secondary`（`#323232`），因为用 `--card` 的话它和凹槽只差 1.01:1，等于不可见。
- **侧栏**也是面板，悬停与发丝线用的是纸自己的值，没有单独一档。

### 实测对比度

2026-10-08 用脚本按 WCAG 公式计算，不是目测：

| 文字 / 表面 | 亮色 | 暗色 |
|---|---|---|
| 墨 / 面板 | 12.3 | 12.6 |
| 墨 / 画布 | 11.2 | 14.5 |
| 次要墨 / 面板 | 6.2 | 6.8 |
| 次要墨 / 画布 | 5.6 | 7.8 |
| 次要墨 / 悬停底 | 5.4 | — |
| 次要墨 / 标签凹槽（闲置标签） | 5.0 | 6.8 |

| 形状与边界（不是文字，没有标准阈值，只记录现状） | 亮色 | 暗色 |
|---|---|---|
| 面板 / 画布（只看色差） | 1.10 | 1.15 |
| 发丝线 / 面板 | 1.27 | 1.35 |
| 标签板 / 凹槽 | 1.22 | 1.19 |

强调色深青 `#1f7a72`：白字压在上面 5.1:1，作为文字落在面板上 4.9:1（沿用 `App.css` 注释里的实测值，这次没有重算）。

**已知的薄处：** 亮色里「面板 / 画布」只有 1.10:1，边界靠发丝线承担。
因此 `prefers-contrast: more` 把 `--border` 抬到前景色的 55%，实测发丝线对面板 / 对画布的对比度是
亮色 3.2 / 3.1:1、暗色 4.9 / 5.2:1，两个主题都过非文字的 3:1。
（这一块改版前取的是 34%，注释写「约 3:1」，实测只有亮色 1.9:1、暗色 2.7:1，这次一并修正。）

## 6. 系统材质接缝

规则的核心是一句话：**材质只能让画布变半透明，别的什么都不能。**

- 受影响的只有两处：**画布**（面板之间的缝隙）和**标签栏**（它本来就是画布）。
  面板、菜单、对话框永远是实色——文件列表叠在实时模糊上读不了。
- 机制：`<html data-window-material>` 由 Rust 侧决定，取值 `mica` / `acrylic` / `vibrancy` / `blur` / `none`。
  材质下根元素不再绘制，`body` 用画布色的 `--pane-alpha` 份额绘制，剩下的份额就是透出的桌面。
- **`--pane-alpha: 100%` 即关闭整个接缝**，其余什么都不用改。

| 材质 | `--pane-alpha` | 为什么 |
|---|---|---|
| `none` | 100% | 没有背景可透，实色画布 |
| `mica` `acrylic` `vibrancy` | 85% | 平台已按窗口的明暗给它上了色 |
| `blur`（目前只有 niri） | 95% | 它就是桌面本身，没有任何上色 |

**为什么 `blur` 要单独设：** 浅色外壳叠在黑色壁纸上，闲置标签文字（次要墨压在凹槽上）的对比度随画布份额变化：

| 画布份额 | 85% | 90% | 95% | 100% |
|---|---|---|---|---|
| 亮色 / 黑壁纸 | 3.6 | 4.0 | **4.5** | 5.0 |
| 暗色 / 白壁纸 | **4.2** | 5.0 | 5.9 | 6.8 |

95% 刚好过 AA，余量很薄。

**没有 `prefers-reduced-transparency` 的守卫：** Windows 上这个设置会先把材质报告成 `none`；
macOS 的材质视图自带实色回退。平台自己决定，CSS 不去二次猜测。

## 7. 颜色

- **强调色** 经 `--primary` 一个入口出去：填充按钮、焦点环、选中、当前标签的下划线、容量条。
  窗口失焦时只保留 25% 的色相（其余向次要墨靠拢），回到前台时颜色回来就是「窗口回来了」的信号。
- **语义色**（`--destructive` `--success` `--warning` `--info`）**不**走强调色接缝：
  一次失败的复制，在后台窗口里同样是失败的。
- **内容色** 是封闭的两组：文件夹（`--folder` 金线 + `--folder-body` 黄体）和六种类别色
  （蓝：文档与代码；紫：图片、视频、字体；绿：表格与证书；橙：媒体与压缩包；玫红：PDF、密钥、可执行文件；青：桌面、音频、数据库）。
  它们说明「这东西是什么」，**不**随强调色变化，否则一个普通文件夹会在用户选了某个强调色之后看起来像被选中。
  同一组六色也用作 Space（用户自建工作区）的身份色（`--color-tone-*`）——这是用户选的**内容**，不是外壳的配色。
- **选中** = 强调色 20%（暗色 26%）铺在行上。文件列表的行和网格单元**额外**有一条同色相的 1px 发丝线
  （`--selection-edge`），它专门负责区分「选中」和「悬停」——没有它，两者在某些底色上只差几个 L*。
  「选中」必须明显高于「悬停」（约 2.2 倍），否则它只是个指针。
  导航行、菜单行、命令面板行用 `row-active`（一层 7% 的墨色），**没有**发丝线。
- **图标**：界面图标用 Solar 的 `line-duotone`，第二笔取强调色混合墨色（58%）；
  携带含义的图标（类别、语义、文件夹）**退出**这个规则，保持自己的色相。

## 8. 「AI 味」清单

下面这些处理会让应用一眼看上去是「生成出来的」。**默认不用**；确实需要时，先说明它替代了什么。
「出处」一栏标明这条禁令是 `App.css` 里早就写明的，还是这次改版新增的。

| 不要 | 为什么 | 出处 |
|---|---|---|
| 玻璃、磨砂、`backdrop-filter` 做外壳 | 见 [§1](#1-为什么不是液态玻璃)。 | 本次 |
| 渐变背景（含柔和的粉紫、蓝紫「氛围」） | 色彩应来自内容。外壳上的渐变在每个平台上都像换了个皮肤。 | 本次 |
| 光晕、发光、泛光、偏紫偏粉的彩色阴影 | 阴影只说明「这个东西搭在平面上」。（亮色阴影取墨色 `#2b3038`，不算彩色。） | 代码 + 本次 |
| 导航行、菜单行、命令面板行选中时加描边环 | 环让行读起来像「可以点的控件」，而不是「你在这里」。（文件行和网格单元的 1px 选中边线不在此列。） | 代码 |
| 主按钮渐变、高光、斜面 | 实色加接触阴影就够了。 | 本次 |
| 胶囊形的搜索框、标签、徽标 | 圆角是安静的、小的；全圆只留给状态点和容量条。 | 代码 |
| 任何超过命令面板和对话框的圆角（16、20、24px） | 浮层不应比它所属的窗口更圆。 | 代码 |
| 弹性、过冲的动效 | 机械感。 | 代码 |
| 全大写加字距的分组标题 | 对汉字无效，对拉丁字母也只是装饰。 | 代码 |
| 彩虹式强调色；给外壳的固有分区（侧栏各组、工具栏）各配一个颜色 | 外壳只有一个饱和的声音，而且是用户选的。（Space 的身份色是用户选的内容，不在此列。） | 本次 |
| 给图标套强调色洗过的彩色底板 | 会把每个卡片变成一个彩色筹码。（中性的 `bg-secondary` 底板，如项目卡片里的，不在此列。） | 代码 |
| 带 ✦ 的「AI」装饰图标与渐变文字 | 同上。 | 本次 |
| 第三种焦点环透明度 | 控件和行各一种，没有第三种。 | 代码 |
| 往窗口里再加一级「卡片套卡片」的阴影 | 层级是两级加一条线。 | 本次 |

## 9. 改之前先问

1. 这个改动要的值，在 [§4](#4-封闭的刻度) 的刻度里吗？不在的话，改的是刻度还是这一处？
2. 把 `--pane-alpha` 设成 100%、再切到另一个平台，它还完整吗？
3. 亮色和暗色都看过吗？暗色没有阴影，层次完全靠色差和发丝线。
4. 用了新的颜色吗？它是「内容色」还是「外壳色」？外壳不该有新的颜色。
5. `prefers-contrast: more`、`forced-colors`、`prefers-reduced-motion` 下会怎样？
   强制色模式会去掉 `background-image` 与 `box-shadow`，但会保留边框和实色填充——这也是面板用真正的
   `border` 与 `background-color`、而不是图像叠层的原因。

### 改 token 时的几个坑

- **启动画面从 `App.css` 读值。** `vite.config.ts` 的 `themeBootStyles` 在构建时从第一个
  顶格的 `:root { }` 和 `.dark { }` 块里按名字读 `--background`、`--border`、`--accent-default`，
  注入到 `index.html` 的首帧样式。改名或挪走这三个，构建会带着名字报错。
  **不要在这些块的注释里写形如 `--background:` 的文字**，它会被当成声明匹配到。
- 需要成为真正变量的几何值（`--sidebar-width`、`--tab-strip-height`）要写在**同一个** `:root` 块里，
  不要另起一个 `:root` 放在它前面。`@theme inline` 里的 token 会被内联进工具类，不会输出成变量。
- 类名与 token 名是 TSX 的接口：`content-panel`、`tab-trough`、`tab-pill`、`row-active`。
  改它们要同时改调用处。

## 10. 尚未验证的与已知差距

- **`prefers-contrast: more` 的效果只用脚本算过，没有在真机的高对比度设置下看过。**

- **Mica / Acrylic / vibrancy 的 85%** 是按「平台已上色」推断的，没有在真机上、用各种壁纸量过。
  只量了裸模糊的最坏情况。
- **视觉验证**用的是无头 Chrome 渲染一张用真实编译 CSS 搭的静态页，覆盖亮色、暗色和 Mica 的模拟壁纸。
  没有在三个平台的真实 WebView（WebView2、WKWebView、WebKitGTK）里逐个看过。
- **暗色的层次**完全依赖 1.35:1 的发丝线和 1.15:1 的色差；如果真机上觉得扁，
  首先考虑把暗色画布调深一两级，而不是加阴影。
