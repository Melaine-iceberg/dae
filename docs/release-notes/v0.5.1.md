# dae v0.5.1

界面与引擎拆分的收尾版本：应用外壳从 Tauri + React 换成 **Rust + Qt Quick**，仓库里不再有第二套前端。功能面上没有新增，这一版交付的是"同一个 dae，换了一副骨架"。

---

## 这一版最该先知道的三件事

1. **外壳换成 Qt Quick。** `apps/dae` 是唯一的 GUI 进程，界面由 `qml/` 直接渲染；Rust 侧不再有 WebView2 / WKWebView。安装体积与冷启动都随之变化。
2. **Tauri 与 React 已从仓库删除。** `src-tauri/`、`src/`、`index.html`、`vite.config.ts` 均不存在，旧 CI 一并下线。`package.json` 只保留发布工具链。
3. **更新器改为按预览版发现。** dae 只发预览版，`releases/latest/download/` 永远解析不到东西，因此发现逻辑在首选 URL 失败时回退到 GitHub releases API。

---

## 外壳

- 窗口 chrome 由 QML 绘制，Windows 上带 Mica 背景，Linux 上走 Wayland 原生模糊（`ext-background-effect-v1`）。
- 三个平台的 IME 失焦行为统一：以 `preeditText` 非空为前置，Windows 走 `ImmNotifyIME(CPS_CANCEL)`，macOS / Linux 走 `QInputMethod::reset()`。
- QML 在构建期编译为 AOT 单元，发布包里没有 `.qml` 源码文件。
- Windows 的 MSIX 现在打包完整的 Qt 运行树（`platforms/`、`qml/`、`multimedia/`），不再是单个可执行文件。

## Linux

- 首次提供 **`.deb` 与 `.rpm`**：`/usr/lib/dae` 存放完整 Qt 运行树，`/usr/bin/dae` 是一个 `exec` 启动器而不是符号链接 —— Qt 用进程启动路径推导应用目录，符号链接会让 `qt.conf` 失效。
- `.deb` 的 `Depends` 由 `ldd` 反查 `dpkg -S` 得出，`Recommends` 列出预览播放需要的 GStreamer 组件。
- 便携 zip 保持根目录布局：可执行文件加 `platforms/`、`qml/`、`lib/` 同级。

## 更新

- 首选 `https://github.com/Melaine-iceberg/dae/releases/latest/download/latest-qt.json`；失败且端点仍是默认值时，回退到 `api.github.com/repos/Melaine-iceberg/dae/releases`，取第一个带 `latest-qt.json` 的非草稿发布。
- `DAE_UPDATE_ENDPOINT` 指定的端点不做回退。
- 归档仍用原来的 minisign 私钥签名，签名内嵌在 `latest-qt.json` 里。

## 修复

- `apps/dae` 的 build script 与 `dae-qt` 的构建产物之间存在顺序竞态，冷缓存下会读到尚未生成的 `plugin.qmltypes`。
- 两处单测写死了 Windows 路径（别名目录、日志目录），在 Linux / macOS 上必然失败。

## 仍需注意

- **MSIX 形态下"设为默认文件管理器"不生效**：打包应用的 `set()` 写入落在 Helium 虚拟化的用户 hive 里，到不了真实注册表。便携版与 `.deb` / `.rpm` 不受影响。详见 `docs/packaging.md` §3.3。
- dae 仍在 0.x，`settings.toml` 的字段与快捷键绑定格式仍可能变化。
