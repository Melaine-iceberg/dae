三套视觉方向

你的判断是"整体气质平庸"。这份文档先给出这个感受的物理原因，再给三套彼此可区分、 并且都能在 Qt Quick 里真做出来的方向。每套都标了改动面与最坏情况，供你决定改到多深。

0 次全仓 52 个 QML 文件的阴影 / 模糊 / ShaderEffect 用量
4–6 级raised 与 canvas 的实际亮度差，远在可感知分层之下
116 px三段外框固定高度，是这套"通用工具感"的结构来源

为什么它看起来像通用工具

01

整个界面没有海拔

DropShadow / MultiEffect / FastBlur / ShaderEffect 在 52 个 QML 文件里出现 0 次。菜单、对话框、命令面板、侧栏、列表全部处在同一光学平面， 唯一的层级手段是 1 px 线和 #0b0c0e → #16181b 之间 6 级的亮度差。 而有纵深的应用把"浮起来"当作不占面积的层级信号——你缺的正是那个信号。

02

暖橙是唯一的作者性，但它没有被用成语言

选中行是"左侧 3 px 橙条 + 8% 橙色蒙版 + 底部 1 px 线"三件套叠加，其余地方橙色基本不出现。 于是十年来所有文件管理器都在用的那套语法被原样复用，橙色只成了"这个 app 的主色"， 而不是"这个 app 用颜色在表达什么"。

03

三段等高的外框把内容压成了三段灰带

标题 44 + 导航 44 + 状态 28，三段同色（#0b0c0e），段与段之间只靠 1 px hairline 分隔。 上半屏因此是一条 88 px 的连续灰带，视线的第一个落点是"一片空白"而不是"文件"。

方向 A

仪器台 · Instrument Bench

把文件管理器做成一张测量仪器：每个面板有一条自己的"脊"，定位标记、选中轨、分组刻度都住在里面， 数字用等宽对齐。不靠装饰，靠"这里每个像素都在汇报状态"来获得辨识度。

记忆点

左侧一条 16 dp 的脊：底色再降一级（#070808），选中时整条轨从脊里亮起来， 分组边界在脊上打刻度，树形展开的引导线也画在脊里——所有"位置信息"被收进同一条通道。 它不占用内容宽度（12 inset + 16 脊 + 8 = 36 的内容原点），却让每一屏都有一条属于自己的刻度尺。

三条取舍

  • 用一条连续的脊，也不要给每一行加装饰性的选中态
  • 用等宽数字，也不要为了对齐好看去缩小字号
  • 宁可整屏只有一个饱和色，也不要让第二处染色变成假按钮

改动面与风险

小。Theme.qml 换值 + 给面板加一个 16 dp 的脊槽位即可，控件阶梯原本就是奇数档 （20/24/28/32/36 已在 4 dp 网格上），压紧后不破格。
最先见效：Theme.qml → FileList.qml → Sidebar.qml。

最坏情况

12 万行列表：脊用每行 Rect 可接受（不是全高矩形，不需要裁剪）； 若图省事用一整条全高矩形挂在 ListView 上，会被 12 万行的 contentHeight 撑开—— 必须每行绘制。
亮色主题里脊的 #e6e4de 与 canvas 差 4 级，偏弱，需要 #e2dfd8 兜底。

方向 B

纸 · Paper

假设这张列表会被读，而不是被扫。去掉几乎全部的线，用版式、字重和留白建立层级， 选中不画块而画一道下划线。安静到极致之后，品牌色只做印章使用。

记忆点

整屏零线：没有行分隔线、没有标题栏下边线、侧栏没有分组线。层级全靠 行高（36 dp）+ 字重对比（400 / 600）+ 留白节奏。选中态是一道 2 px 下划线落在文件名底下——像在纸上划了一道重点，而不是把整行涂色。 这是三套里唯一敢把"选中"做得这么轻的方案，因此也最不像通用文件管理器。

三条取舍

  • 宁可一行只读一个变量（名称），也不要四列等重的表格
  • 宁可字号差 3 级，也不要靠灰度差 4 级来分主次
  • 宁可选中态轻到需要适应，也不要满屏色块

改动面与风险

大。这不是换值：需要重排主列表的四列结构、给非活动行定义新的字重规则、 重做选中态、并且移除全仓 Theme.hairline 的大量调用点。 最先见效：FileList.qml 的行样式 → Theme.qml 的字阶 → Sidebar.qml 的分组头。

最坏情况

没有线的表格在 120 列的宽窗口 和 12 万行的长列表 里都容易失去横向引导—— 需要靠表头随滚动吸顶补偿（目前没有吸顶表头）。
选中态 interactive = ink 会与焦点环语义冲突，键盘用户的可见性必须另设方案。

方向 C

井 · The Well

把当前"所有东西同一平面"的结构反过来用：外框（标题、侧栏）是实心的石面， 内容区是凿进去的一口井，比外框更深。轻重关系一翻，层级不需要阴影就能读出来。

记忆点

面板井 + 唯一一层浮起：标题/侧栏是 #1b1d20 的石面，内容区是 #0b0c0e 的井底，中间留 10 dp 的缝。面板自身带一道 inset 0 1px 0 rgba(255,255,255,.07) 的顶光——这在 Qt 里只需一个 多色渐变矩形，成本为零。菜单/命令面板/对话框是整屏唯一允许浮起的东西， 带 10/24 的投影。于是"浮起"变成了一个有意义的状态，而不是装饰。

三条取舍

  • 宁可只有一层海拔（菜单），也不要给卡片和行都加影子
  • 宁可反转明暗关系，也不要靠加粗边线制造分区
  • 宁可缝比线宽，也不要在面板之间画分隔线

改动面与风险

中。Token 只需换值并新增一个"浮起层"角色，但 所有外框表面都要重新排布： 标题栏、侧栏、列表、预览、终端现在都是紧贴的，加 10 dp 缝等于改五处锚点与 shellTitle/shellNav/shellStatus 的耦合。
最先见效：ShellWindow.qml 的面板锚点 → Theme.qml → MenuList.qml。

最坏情况

无材质环境（material = none）下石面与井底同时出现，若亮度差压到 5 级以内， 整扇窗会读成两种脏灰——这是三套里对取色最敏感的一套。
系统强调色覆盖 interactive 时，顶光的冷白会让强调色偏脏，需要给 accent 加一道降低饱和的补偿。

推荐

先做 A，但它不是终点

你的痛点不是"不够漂亮"，是没有记忆点。三套里 A 是唯一能在一周内让用户 说出"这个文件管理器长得不一样"而不用重排任何布局的方案——脊是一个局部组件， 改动面小、可回退、对 12 万行列表几乎零成本，而且它保留了你已经付过代价的那套 暖橙信号色与克制圆角。

B 的记忆点最强，但它把"选中"做成下划线，等于重新教育用户的肌肉记忆； 对一个日常工具来说，这需要产品上有足够自信才成立——如果 dae 想走"给写作者/研究者的 文件管理器"这条窄路，B 才是对的答案。

C 最"现代"，也最容易被抄成另一款通用 app；它的价值在于把浮起这个概念 引进来。这件事其实可以单独摘出来做——不管选 A 还是 B，菜单与命令面板都该有且仅有 一层海拔。我建议把 C 的这一条作为 A 的附加项吸收。

所以"改到多深"和"选哪套"其实是同一个问题。三套里只有 A 能切两刀： 第一刀只动 Theme.qml（收圆角与行高、压紧外框）、FileList.qml （画脊与等宽数字）、Sidebar.qml（脊的槽位），改完就能整窗回滚； 第二刀再加浮层海拔与动效一致性。B 的删线、去色相、抬行高三件事互为前提， 拆开做任何一件都会让界面更糟；C 只改一部分面板会让亮石面与暗井底同时存在。 也就是说——选 A 等于保留了"改到一半就停"的权利，这对一个已有 52 个 QML 文件、 还在正常发版的项目，比纯粹的视觉强度更值钱。

STEP 1 你选定方向与深度。只换视觉层 → 直接进落地；要动结构 → 先进体验规范。
STEP 2 体验专家出主窗口的区域权重、密度节奏、焦点可见性与缩放行为规范。
STEP 3 工程按批次落地：token → 列表 → 侧栏 → 浮层，每批可独立走查与回退。
