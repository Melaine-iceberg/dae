# 设计语言 v2 —— Atlas

状态：**已采纳**（2026-10-20，取代 [`design-principles.md`](design-principles.md) 的「安静桌面 / Quiet Desk」方向）

**token 的唯一来源仍然是 `src/App.css`。** 这份文档只解释为什么 token 是这个形状、窗口为什么这样分层，以及改之前该问什么；数值不一致时以 `App.css` 为准。

---

## 一句话

> **一层冷色的框架（chrome），几张纸（panel），一个强调色。**

---

## 1. 为什么要换

v1 的判断没有错的地方：实色、不依赖系统材质、颜色留给内容、跨平台一致。问题出在**没把窗口本身画出来**：

- 画布和面板都是浅色，靠 1px 描边区分，窗口读起来像「一堆等价的卡片浮在灰底上」，没有内外之分。
- 导航栏和内容区同色同权，视线没有起点；标签栏透明，顶边等于不存在。
- 工具栏占两行（路径行 + 控件行），为了放下控件牺牲了 70px 的列表高度——而文件管理器最贵的像素就在列表里。
- 中性色偏暖（OKLCH chroma ≈0.013，色相 85–95°），在整窗尺度上读作「纸」，和一个饱和的强调色放在一起则读作「旧」。

v2 只改这四件事：给窗口一个框架色、给面板一张纸、把工具栏收成一行、把中性色转冷。

---

## 2. 三级层次（token 的骨架）

```
--sidebar   框架：标签栏 + 导航栏 + 面板之间的缝隙（同一个色）
--card      纸：内容面板、终端、菜单、对话框
--background 画布：只在面板没盖住的地方出现（对话框背景、启动闪屏）
```

亮色：`#f5f8fc` → `#ffffff` → `#edf0f6`。
暗色：`#0f141c` → `#161c26` → `#0a0d13`。

三者都刻意接近：**层次由「一个台阶 + 一条 1px 边 + 一道顶光」共同承担，任何单一手段都太弱。**
`--panel-bevel` 是那条顶光——亮色是白，暗色是 4.5% 的白——它让一张近白色的纸在近白色的框架上仍然
读作「浮起来」，而不是「挖下去」。

暗色下阴影几乎不可见，层次完全交给明度和顶光；亮色下再加一层很大的负偏移软阴影，
只负责说「这张纸躺在框架上」。

## 3. 窗口解剖

```
┌──────────────────────────────────────────────────────────────┐
│ 标签条 44px：chip / + / 窗口控件                  ← --chrome  │
├────────────┬─────────────────────────────────────────────────┤
│ 导航栏      │ ┌─────────────────────────────────────────────┐ │
│ 248px      │ │ 工具栏 48px：路径胶囊 · 搜索 · 视图 · 面板   │ │
│ --chrome   │ ├─────────────────────────────────────────────┤ │
│            │ │ 列表／网格／分栏            ← --card 的纸    │ │
│            │ └─────────────────────────────────────────────┘ │
└────────────┴─────────────────────────────────────────────────┘
```

**框架是一个 L。** 标签栏、导航栏、面板周围的缝隙同色，构成一个连续的框架，内容是一张压在它上面的纸。
这条规则的具体后果：

- 导航栏**不再**是 `.content-panel`：它没有自己的描边、圆角和阴影，它就是框架。
- 标签条不画分隔线。chip 之间的竖线在画布上是为了把散落的标签拢住；在有色框架上，它只是这一行里最吵的东西。唯一的结构是那片会滑动的白色 `tab-pill`。
- 面板之间只靠 8px 缝隙 + 各自的描边分开，缝隙的颜色是框架色。

**面板永远是实色。** 系统材质（Mica / Acrylic / vibrancy / blur）只透过框架，不透面板——一段文字列表压在活动的模糊上不可读。
`src/lib/window-material.ts` 与 `THE WINDOW-MATERIAL SEAM` 一节没有变，只是 `.bg-chrome` 也加入了「材质生效时停止绘制」的名单。

## 4. 工具栏：一行，路径是脊梁

从两行收成一行，是这次改动里唯一的**结构性**变化。

| 组 | 内容 | 为什么在这里 |
|---|---|---|
| chrome | 侧栏开关 | 贴着前缘，管的是窗口而不是文件夹 |
| travel | 后退 / 前进 / 上级 | 一个凹槽里的三键，读作一件仪器 |
| place | 路径胶囊（`flex-1`） | 行的脊梁，占掉其余控件不要的每一像素 |
| find | 搜索胶囊 | 空闲 176px，聚焦 256px，<1360px 折成放大镜 |
| act | 刷新 / 收藏 | 对「当前文件夹」做的两件事 |
| view | 视图 / 筛选 / git 分支 | 改变你看到什么 |
| panels | 分栏 / 预览 / 终端 | 贴后缘，中间长缩时它们不动 |

**路径是唯一持有「值」的控件**，所以它是填充的胶囊而不是裸面包屑：看起来像输入框，才不需要 tooltip 教人「点这里可以编辑」。

窄窗口的让位顺序写在 `TOOLBAR_OVERFLOW_CLASS` / `TOOLBAR_OVERFLOW_GIT_CLASS` 里：
收藏（文件夹右键也有）→ 分栏（每标签页的布局选择）→ git 分支（上下文，不是控件）。
搜索在 1360px 以下折成放大镜，聚焦时展开——**一个没人用的搜索框不该是路径读不全的原因**。
路径本身有 `min-w-40` 下限，面包屑在挤压时折叠中段（`…`），当前文件夹名永远保留。

## 5. 排版与密度

六步字号梯度没有变，只有 `title` 从 18px 抬到 19px（`--text-title`），字重 640、字距 -0.016em。
理由：19 与 14 之间有五步，高于此前的四步，标题与正文的**差**而不是两者本身，才承担页面的平静。

列表行密度上调一档：`28 / 34 / 44`（compact / comfortable / spacious）。
14px 的文字在 34px 的行里才真正有上下留白，一屏 40 个文件是「一眼可读」，而不只是「勉强可读」。

## 6. 状态词汇

| 状态 | 表现 | 位置 |
|---|---|---|
| hover | 元素自身墨色 7% 的薄雾（`.state-layer`），或 `--accent` 填充 | 所有可点区域 |
| 选中（行/格） | 强调色 14%（暗色 30%）填充 + 42% 描边 | `.bg-selection` |
| 当前所在（导航） | `--sidebar-accent` + 13% 强调色叠加（`.row-active`），字形转为强调色 | 导航行 |
| 焦点 | 控件 2px `--ring/40`；行内嵌 1px（虚拟滚动会裁掉外环） | 全窗 |
| 拖放目标 | 10% 填充 + 内嵌 2px 强调色环（`.drop-target`） | 列表、网格 |

选中之所以带一条描边：填充只表达「被选中」，描边才表达「和 hover 不是一回事」——两者在明度上只差几级。

## 7. 颜色边界

- **强调色跟随系统**（`--system-accent`），未提供时回落到 indigo `#4f5df0` / `#93a0ff`。所有「选中、主按钮、焦点、容量条」都从它派生。
- **分类色（`--tone-*`、`--folder`）不跟随强调色**：它们说的是「这是什么」，不是「这是选中的」。文件夹保持全窗唯一的暖色。
- **语义色（`--destructive` / `--success` / `--warning` / `--info`）同理**，失败在后台窗口里同样是失败，所以窗口失焦时它们不减淡。

对比度都在 `App.css` 的注释里按「所在平面」记录过：亮色下正文 17:1、次级文字 6.0:1；
暗色下 15.4:1 / 7.3:1；强调色两种角色（白字压在上面、作为文字压在纸上）都 ≥ 5:1。

## 8. 改之前先问

1. 这个东西是**窗口**、是**纸**，还是**纸上的内容**？三者各有一个色，选错就没有层次。
2. 这个状态是**位置**（你在这里）还是**指针**（你正指着它）？前者用强调色，后者用中性薄雾。
3. 这个新控件在 900px 宽的窗口里还在不在？不在的话，它有没有第二个入口？
4. 这个数字/颜色是**测过**的还是**看着差不多**？把测的平面写进注释。
